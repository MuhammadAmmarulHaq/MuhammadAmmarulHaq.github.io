## 1. non-negotiable design rules

These were requested explicitly by the owner. Any continuation must preserve them.

1. **CLI / terminal aesthetic.** Monospace everywhere, shell prompts, `ls` style post lists.
2. **The home page must be typable.** A real interactive shell, not an image of one.
3. **No animations.** No blinking cursor, no animated loading dots, no transitions.
   The cursor is a static block that only changes color on focus.
4. **No em dashes or en dashes**, anywhere in content or UI. Plain hyphens only.
5. **Keep it simple.** No React, no Next.js, no bundlers, no npm. Posts are markdown files.
   (React was explicitly offered and declined in favor of simplicity.)

## 2. rebuild from scratch (disaster recovery)

If both local copies are lost, the site is recoverable from the GitHub repo alone:

```powershell
git clone https://github.com/MuhammadAmmarulHaq/MuhammadAmmarulHaq.github.io.git
```

If GitHub is also gone, rebuild the folder from this backup:

```
D:\GitHub Website\        ->  copy the whole tree to a working folder
```

Then restore the publish path:

1. Install git: `winget install --id Git.Git --exact`
2. Install GitHub CLI: `winget install --id GitHub.cli --exact`
3. Authenticate: `gh auth login --hostname github.com --git-protocol https --web`
   (also run `gh auth setup-git` so pushes use that credential)
4. From the project folder: `.\deploy.ps1 "restore from backup"`
5. In repo Settings > Pages, confirm Source = `Deploy from a branch`, `main`, `/ (root)`

Expected build time: 1 to 3 minutes. Verify with a request to the live URL returning 200.

### absolute URLs and secrets

There is **no secret in this backup**. The GitHub token is deliberately excluded
(`.ghconfig/` is skipped and gitignored). Re-authenticate with `gh auth login` instead of
copying a token. If a token file is ever found inside the project folder, delete it and run
`gh auth logout`.

### `index.md` and the terminal

Two-layer design, and the order matters:

1. **Jekyll renders the first screen server side** through `_includes/post-list.html`.
   The `whoami` line, the newest 5 posts, and the hint line all exist in the HTML before
   any JavaScript runs. If JS is off, or a crawler reads the page, the site still works.
2. **`_includes/post-index.json`** dumps every post into a
   `<script type="application/json" id="term-data">` block as an array of
   `{title, slug, url, date, category, tags, description, text}`.
3. **`assets/js/terminal.js`** reads that JSON, overlays a transparent `<input>` on the
   prompt line, and implements the commands. Both lists are sorted newest first. The JSON
   date format is `YYYY-MM-DD`, so lexicographic string compare is correct; `fmtDate()`
   then formats to `Oct 29 2026` so JS lines look identical to Jekyll lines.

Why a transparent input: it gives real keyboard support, IME, mobile keyboards, paste and
autocomplete with no extra code. The visible text is a sibling span (`#term-typed`) kept in
sync, with a static block cursor after it.

Mobile detail: at <= 700px the input font size is forced to 16px so iOS does not zoom on
focus.

Notable details:

- `body` has a 2px `--accent-dim` top border, like a terminal status bar.
- `h2::before` prints a literal `## ` and `h3::before` a `# `, so headings look like markdown.
- Blockquote paragraphs get a `> ` prefix via `p::before`.
- `.ls li` is a 4 column grid with a mobile fallback to a single column.
- Rouge syntax colors are hand mapped to a GitHub-dark-ish palette.
- The only `@media` breakpoint is `max-width: 700px`.

### `assets/js/copy.js`

Appends a `copy` button to every `.prose pre`. Uses `navigator.clipboard` with a
`textarea` + `execCommand` fallback for non-secure contexts. Button label flips to `copied`
for 1.5 seconds.

### `deploy.ps1`

Publish script. Reads identity from the GitHub API so it needs no hardcoded values, sets
git user name and email to the ID-based noreply address, creates the repo if missing,
commits, pushes, and ensures Pages is enabled. Contains a guard because PowerShell treats
native stderr as a fatal error under `$ErrorActionPreference = "Stop"`.

## 5. terminal command reference

| command | behavior |
|---|---|
| `help` | print the command list |
| `man <cmd>` | one line about a command |
| `ls` | all posts, newest first |
| `ls writeups` | only category `writeups` |
| `ls blog` | everything that is not a writeup |
| `ls tags` | tag list with counts, sorted by count |
| `latest [n]` | newest n posts, default 5, capped at 50 |
| `cat <slug>` | title, date, category, tags, description, link |
| `open <slug>` | navigate to that post |
| `search <words>` | substring over title, description, tags, body text |
| `cd posts` / `cd writeups` / `cd about` / `cd ~` | navigate |
| `whoami` | the one-line bio |
| `about` | bio plus about page link |
| `contact` | GitHub link, about link, content policy line |
| `neofetch` | post count, writeup count, latest date, stack summary |
| `date` / `pwd` / `uptime` | the usual |
| `history` | commands typed this session |
| `clear` | wipe the screen |
| `sudo` | joke: "ammar is not in the sudoers file..." |
| `exit` | joke: "there is no exit. only more boxes." |

Shell behavior: arrow up / down walk history, Tab completes command names and post slugs,
Ctrl+L clears, Ctrl+C prints `^C` and aborts the line, unknown commands produce
`bash: <name>: command not found. type help`, flags are tolerated so `ls -la --all` works,
clicking anywhere in the terminal focuses the input. Slug lookup order: exact slug, then
slug prefix, then title substring.

### adding a command

1. Open `assets/js/terminal.js`.
2. Add a function to the `commands` object. It receives `args`, an array of strings.
   Helpers available: `print(text, cls)`, `printPre(text)`, `printList(posts)`,
   `printLink(prefix, href, label)`, `pad(text, width)`, `fmtDate(ymd)`, `findPost(query)`.
   CSS classes for `print`: `dim`, `err`, `strong`.
3. Add a row to the `HELP` array at the top so `help` and `man` list it.
4. Commit and push.

## 6. writing and publishing

### a new post

Create `_posts/YYYY-MM-DD-slug.md`. The filename date is the publish date, the slug becomes
the URL `/posts/slug/`.

```yaml
---
title: "htb: example box"
date: 2026-11-02 14:00:00 +0000
categories: writeups
tags: [htb, linux, privesc]
description: "One sentence used for search results and the rss feed."
---

Body in markdown.
```

- `categories: writeups` places it in both `/writeups/` and `/posts/`. Any other category
  shows in `/posts/` only.
- Images: put files in `assets/img/` and reference `![alt](/assets/img/file.png)`.
- Fenced code blocks get the copy button automatically.
- Supported: headings, lists, tables, blockquotes, bold, links, inline code, fenced code
  with a language, images, horizontal rules.

### recommended writeup structure

1. box info table: name, platform, os, difficulty, ip
2. recon: nmap output, then the full port scan
3. enumeration: what the service exposes, including dead ends
4. foothold: the command that got the first shell
5. privilege escalation: the enumeration that found it, then the escalation
6. lessons: what was obvious in hindsight, what to try first next time

### publish

```powershell
cd C:\Users\ammar\blog
.\deploy.ps1 "post: htb example box"
```

Then wait 1 to 3 minutes and open https://muhammadammarulhaq.github.io

Alternative, no local tools: upload changed files through the GitHub web UI and commit to

### environment notes for automated agents

`git` and `gh` are installed but **not on PATH in a non-login shell**:

```powershell
$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')
```

The GitHub CLI auth may live in a custom config dir:

```powershell
$env:GH_CONFIG_DIR = 'C:\Users\ammar\blog\.ghconfig'
```

That folder holds a plain-text token and is gitignored. It is **not** in this backup.

### incidents already resolved, do not repeat

1. **Repo name must exactly equal `<username>.github.io`**, otherwise the site does not
   serve at the root URL.
2. **The Pages repo must be Public** on the free plan.
3. **Every published `.md` needs a front matter block**, or Jekyll copies it verbatim.
4. **Binary files break the kramdown utf-8 pass** and fail the build. Keep published files
   text. Do not commit images into `_posts/`.
5. **`gh` wrote its token into a folder inside the repo once** and a commit picked it up.
   It was removed from history and gitignored. Never commit `.ghconfig/`.
6. **PowerShell 5.1 does not support `??`.** Use `if ($x) {} else {}`.
7. **PowerShell renders native stderr as an error record.** A git or gh command printing to
   stderr and "exiting with code 1" is often a success. Read the output, do not trust the
   exit code alone.
8. **No timer APIs in the browser tool sandbox.** Use the shell for waits, not `setTimeout`
   inside an evaluate call.
9. **Screenshots need a focused, visible tab.** Focus first.
10. **No em dashes.** Verified repo wide with a grep.
